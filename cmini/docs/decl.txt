decl.c - what the parser (decl.c) adds to c-parser
==================================================

decl.c is the declaration parser of CMini. Compared with decl.cc of the earlier
project c-parser (/abc/c-parser), it has these new parts (comments removed when
the code was compared). Line numbers are not given; use the function names.

Summary of the new functions in decl.c:

    namespaces         NamespaceQual, IsNamespaceName, IsQualifiedExpr
    constructors       ConstructorDecl, ConstructorBody, DestructorDecl,
                       ImplicitInitCtor, HasImplicit, MemberInits, PutBaseInit
    default values     MergeDefaults, NextParam, SameParams, RemoveFromQueue,
                       PutParamDecl, ParameterList, CppOverloaded
    deferred bodies    DeferBody, RecordBlock, ReplaceInPrintList
    token replay       SaveToken, LoadToken, StartReplay, ReplayNext,
                       PeekReplay, PeekSymbol, PeekIsTypeStart
    type names         IsStringName, IsContainerName, ContainerArg, ContainerType,
                       IsStdString (the types are recognised here; the operations
                       are in expr.c, see expr.txt)

Size: decl.c is 2139 lines without comments against 882 in c-parser (51 -> 91
functions).


1. Namespaces
-------------

New functions: NamespaceQual, IsNamespaceName, PeekSymbol, IsQualifiedExpr
(decl.c).

  - namespace X { ... } is accepted; the declarations inside are global (the
    namespace only qualifies the names);
  - the qualification X:: is skipped when the symbols are read (NamespaceQual,
    called by the lexer). using namespace X; is accepted;
  - a qualified name T::f () or T::x at the start of an expression is not a
    declaration (IsQualifiedExpr).

The standard namespace std is handled like the other namespaces; its names
(std::string, std::cout) are recognised by Std (expr.c).

2. Constructors, destructors and member initialisers
----------------------------------------------------

New functions: ConstructorDecl, ConstructorBody, DestructorDecl,
ImplicitInitCtor, HasImplicit, MemberInits, PutBaseInit (decl.c).

  - a constructor with an initialiser list (base class and members), a body
    and an implicit constructor when a class has no constructor and needs one
    for its members (ImplicitInitCtor, HasImplicit);
  - a destructor declaration (DestructorDecl) and the body of a constructor
    or destructor that is read later (see section 4);
  - members with an initialiser in the class (bool x = false;) that are not in
    the initialiser list of the constructor are assigned by MemberInits (after
    the other initialisation); PutBaseInit writes the initialisation of the base
    class.

3. Default parameter values and overloading
-------------------------------------------

New functions: MergeDefaults, NextParam, SameParams, RemoveFromQueue, PutParamDecl,
ParameterList, CppOverloaded (decl.c).

  - default values of parameters: MergeDefaults copies the defaults of a
    declaration into the definition of the function;
  - a method of a derived class with the same name as a virtual method of the
    base but different parameters only hides the base method (SameParams); the
    same parameters make it an override;
  - CppOverloaded: the C functions strchr, strrchr, strstr, strpbrk and memchr
    are declared by the system header (<cstring>), not by the parser, because
    C++ overloads them.

4. Deferred bodies of class members
-----------------------------------

New functions: DeferBody, RecordBlock, ReplaceInPrintList (decl.c).

A method or constructor can use members that are declared after it in the same
class. C++ allows this, so the body is not compiled at once. DeferBody records
the tokens of the body (RecordBlock, up to the matching }) and puts them in a
list (DeferTail). When the class is complete, the recorded tokens are replayed
and compiled (see section 5). ReplaceInPrintList replaces an entry of the
print list (the list of declarations that is translated).

5. Token replay
----------------

New functions: SaveToken, LoadToken, StartReplay, ReplayNext, PeekReplay,
PeekSymbol, PeekIsTypeStart (decl.c).

The parser needs to look at the next symbol in some places (is this a
declaration or an expression? is the next symbol a type?). For this it keeps
the symbol of a record, so that the lookahead can be returned:

  - PeekSymbol and PeekIsTypeStart look at the following symbol without moving
    the input;
  - SaveToken and LoadToken store and restore the current symbol;
  - StartReplay and ReplayNext return the symbols of a recorded list (DeferBody,
    section 4) as if they came from the input again.

The recorded list stays as it is; the replay is only a second reading of it.

Where to look for what (decl.c):

    namespaces                         NamespaceQual, IsQualifiedExpr
    constructors and destructors       ConstructorDecl, DestructorDecl, MemberInits
    default parameters, overloading    MergeDefaults, SameParams, CppOverloaded
    deferred bodies and replay         DeferBody, RecordBlock, ReplayNext
    type names std::string, containers IsStringName, IsContainerName, ContainerType
